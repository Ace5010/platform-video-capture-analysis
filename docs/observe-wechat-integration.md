# Observe 微信模块接入

统一入口：`http://localhost:3000/`。顶部切换内容情报台与微信读取；微信使用单一阅读页，按天查看总结。旧的 `view=manage` 地址自动回到阅读页。

聊天总结采用讨论分段规范 v4：左侧常驻讨论标题，右侧连续展示标题、简短简介和“查看讨论原文”入口，窄屏保持两区同时可见。简介通常两三句，不标人物，不展开长文、观点对照或原话节选；原讨论保留全部相关消息与引用链。点击标题定位相应简介，返回原文前的阅读位置会保留。旧版总结兼容读取，仅展示已有标题和导语；重新生成时使用新规范，历史版本与费用回执保留。修改规则本身不触发付费生成。

添加群：在电脑 localhost 工作台的群列表下点击“＋”，输入完整群名，查找后确认添加，再点击“读取并总结”。查找只访问当前已配置微信账号的群联系人，不读取消息或调用模型；同名群无法唯一确认时提示先在微信修改群名。新增群分别保存配置、归档、总结和费用记录；原有群的数据位置保持不变。HTTPS 工作台继续只提供已保存内容的阅读。

“读取并总结”弹窗默认选中“从上次总结继续”；尚未成功总结的群默认“全部聊天”。“全部聊天”和“指定日期”作为次要选择，日期仅用于确定本次处理范围。模型用按钮选择，弹窗不放读取历史或功能解释。“⋯ → 读取记录与积分”独立展示每次执行及每日总结明细；“⋯ → 查看当天全部聊天”提供完整消息和筛选，附件、图片、网页正文只在原文中显示。

## 代码与运行

- `app/wechat-workspace.tsx` / `.css`：原生 React 微信工作区；无 iframe、无 ChatLab 整站嵌入。
- `lib/observe-navigation.ts`：模块与内部入口恢复。地址栏和 localStorage 仅持久化模块/入口，不持久化群名、正文、搜索词。
- `host_service/wechat/`：从已验证的微信项目接入归档校验、完整话题讨论、总结规范、CodeBuddy 生成与读取任务。`vendor/` 保留固定版本校验及许可证。
- `/api/wechat/*`：与视频共用主机服务，沿用密码会话和 CSRF。正式 HTTPS 工作台通过原有私有通道开放已归档的群列表、日期、总结、完整讨论和原文筛选；未登录、其他来源及直接局域网访问不能读取微信归档。管理记录、读取聊天和付费生成继续在打开归档前检查电脑 localhost 权限。
- 手机与电脑读取同一份归档，不创建云端数据副本。远程群列表排除账号标识、批次和任务记录；正文接口使用 `private, no-store`，不嵌入静态页面或写入浏览器持久存储。筛选仅通过带 CSRF 的 POST 查询，消息按文本渲染，不执行消息中的 HTML。共享 `/api/state` 和匿名静态页面继续不含微信内容。
- 阅读接口提供不透明的归档版本标记，随消息、已发布总结、资源记录与日期边界变化；不包含路径、账号或任务明细。手机在页面可见时每 15 秒及重新回到页面时检查，变化后刷新日期与总结并保留所选日期、话题和阅读位置。网关保留所选群标识，成员筛选跟随当前群，支持超过 100 个话题的原文读取。外网版本需发布后生效；Cloudflare 转发需要信任其处理请求内容。
- 原有 `scripts/launch.ps1` 即可启动全部工作台。无需 3110 或 3113 服务。

## 数据和依赖

本次没有重建数据库或搬迁私人数据。视频继续使用 `data/host-service/monitor.sqlite3`；微信继续使用 `D:\vibe项目\WeChat-Reader\private`，包括原始归档、ChatLab 数据库、总结版本、模型回执和费用记录。

原有固定版本 ChatLab CLI、CodeBuddy CLI 安装分别复用 `WeChat-Reader/runtime` 与 `WeChat-Reader/buddy-runtime`。它们是本机依赖，不是独立网站。读取子进程使用已有全局 Python（已安装 cryptography 与 zstandard）；Observer 主机使用 `zstandard==0.25.0` 解析归档内已保存的压缩消息，不在主机进程加载扫描依赖。该解压组件纳入现有 `requirements-asr.txt` 安装入口。

读取先短暂复制所选数据库与 WAL，在复制前后核对来源状态，最多重试 5 次；随后仅对稳定副本执行原有解密、WAL 边界检查和完整性检查。微信在解密期间收到新消息不会使已取得的副本失效；复制窗口内持续变化仍停止，不退回缺少 WAL 的旧数据。副本随读取临时目录清理。

群列表元信息按配置、批次、导入回执及总结文件变化失效，任务状态始终重新读取。附件进度单独从小型预期清单与资源回执计算，不因每张图片的保存重新解析全部历史。前端同一群的轮询请求不重叠，慢响应也能更新进度。

可选环境配置：`OBSERVE_WECHAT_DATA_DIR` 指定归档根目录，`OBSERVE_WECHAT_RUNTIME_ROOT` 指定上述 CLI 所在目录，`OBSERVE_WECHAT_PYTHON` 指定读取用 Python。当前配置继续复用原有已指定账号与群；页面不扩展账号授权范围。

旧项目 `scripts/launch-reader.ps1`、`serve.ps1`、`read-once.ps1` 已转到 Observe；旧启动脚本备份位于 `scripts/before-observe/`。保留旧源码以便回退，不再作为日常入口运行。

## 行为约定

- 打开页面、筛选、刷新已保存记录均不扫描微信、不调用模型。真实读取/导入和生成总结需要用户在所属模块确认目标与范围。
- 默认总结模型仍为 CodeBuddy 的 DeepSeek-V4.1-Flash high，保留 GLM low 与 Hy4 high；使用现有讨论简介规范和完整讨论归属校验。
- `POST /api/wechat/analyze` 将读取、导入、资源完整性检查与逐日总结接成后台任务。三种范围均使用明确的开始/结束时间；继续读取以成功发布总结的截止点为准，边界当天会重新取齐上下文并更新该日简介。未变化的当日来源指纹跳过重新总结；首次读取全部聊天从本机可读取历史开始。
- 总结费用使用原始回执，保留旧结果。父任务保存每个逐日任务标识，即使中断也可恢复已发生积分；未知积分保持待核实，不记作零，也不自动付费重试。一个日期失败后停止后续总结，之前完成的结果与费用保留。`GET /api/wechat/history` 合并旧记录及新流程，子任务不重复计入总费用。
- 关闭弹窗或切换模块不取消后台任务。完成后更新阅读内容并保留滚动位置。空范围不调用模型；读取不完整或资源校验失败时停止，旧结果继续可读。
- 新版总结自动忽略旧版展示字段（今日重点、要点、单列观点、细节和结论），原始模型输出保留在执行记录中；消息覆盖、引用、原话与人物归属仍须完整通过校验。失败原因、执行阶段及已记录积分会保存并传给页面，不自动付费重试。
- 生成时使用本次任务内的短消息编号，映射另存于私有执行目录，不改变归档 ID 或来源指纹。发布前自动修复可唯一核实的长编号尾部错误、引用列表格式、已声明证据与明确回复链的讨论归属；失真的可选引语移除，正文和完整讨论保留。修复记录写入原回执，再执行完整校验；已知跨日编号、有歧义的匹配和无依据的消息归属不自动猜测，不追加模型调用。
- 讨论标题列表与简介正文独立滚动；按群和日期保存阅读位置。模块切换保留两边会话状态；视频暂停并撤下媒体地址，回来保持暂停和进度。
- 微信原文按当前归档查询；“查看前后文”返回原群前后各 15 条，解除成员/关键词筛选以便核对上下文；话题“完整讨论”返回全部归属消息及相关引用链。
- 读取任务区分运行、不完整、已保存待导入、导入完成、失败和状态待核实。已提交任务不因模块切换而取消。

## 按日期清理与存储上限

“更多操作 → 清理聊天记录”只在 localhost 显示并允许调用。先选择当前群的起止日期（北京时间、包含两端自然日），预览聊天、总结、附件及预计释放空间，勾选确认后执行。预览指纹与执行前数据必须一致；读取、总结或未核实任务未结束时禁止清理。

清理会重写所选群受影响的批次，保留日期外全部消息与共享图片，清理对应总结、旧版本及包含聊天内容的辅助输出；积分回执、任务记录、原微信数据及其他群保持不动。当前群未被任何消息或保留总结回执引用的缓存会一并清理，数量单独列出。ChatLab 本地索引仅删除选中时间段消息并回收数据库空页。旧副本同步压缩，清理日期记入排除范围，后续读取不会自动把已清理消息重新导入。

操作保存可续作日志，文件被占用或中断后按原日期继续；已完成请求可幂等重放。正式删除仅由界面确认触发，开发验收只在隔离数据上执行真实删除，对生产归档仅做预览和哈希核验。

所有群的附件空间合计上限 3,000,000,000 字节，磁盘最低保留 5,000,000,000 字节。达到限制只停止新增文件，不自动删除已有内容；按指纹复用已有图片不增加占用。并发写入在进程内及 Windows 文件锁下核对总量。日志、文字归档及微信客户端自己的缓存不计入附件上限，但新增附件始终检查磁盘剩余空间。


## 图片诊断与单张重试（2026-10-26）

原文区按实际文件检查区分“仅有缩略图”“未找到图片文件”“图片解析失败”。可用缩略图按 `tier=thumbnail` 保存并标注；缺项状态保留，`summary_images` 明确排除该层级，即使错误标为 ready 也不会送入模型。已有缩略图按指纹复用，原图到达后优先升级；不同来源标识间也优先选择 `_h.dat`。

localhost 的图片缺项提供“重试”，仅提交当前群及消息 ID。服务端校验归属、CSRF、任务互斥和清理状态，重新检查这一条本机图片；旧记录缺少文件定位信息时只刷新该消息所在秒的源记录。重试不操作微信界面、不下载视频、不调用模型，不修改原聊天批次或总结。远程入口只读，不开放重试写操作。

兼容 CLI：`resources --images-only` 仅检查本机图片；`--message m_…` 限定单条图片。批量维护可刷新缺少定位信息的旧图片，校验消息 ID、发送者、时间、类型和正文一致后使用新定位信息。后台读取任务可显式设置 `images_only: true`，沿用任务互斥与历史回执。完整图片缺失仍按缺项记录，未完成总结不会自动重跑。

WXGF 解码现在区分尾部校验数据和有效 HEVC 帧头，保留透明层、从属帧与截断校验。验收包括隔离资源/接口测试、1440/390/320 页面、真实单张重试、完整恢复图片像素解码；证据在 `outputs/wechat-image-retry-20261026/`。原有批次、总结和费用回执保持不变。

### 提交与执行

“读取并总结”支持勾选多个已添加群、全选和清空选择，一次提交统一的范围与模型。每群完成读取和逐日总结后再执行下一群；普通失败保留该群回执并继续。页面显示各群正在读取、正在总结或排队中，运行期间可追加其他群，同一群已有任务时禁止重复入队。继续读取仅在所选群均有总结进度时可选，各群沿用自己的进度。

localhost `POST /api/wechat/analyze-batch` 接收 `groups`（最多 100 个、不重复）、`scope`、可选 `date`、`mode`、`request_id` 和 `confirmed`。先校验整批，再原子保存 `analysis-queue.json`；群任务使用由批次和群派生的稳定 ID，沿用各群的 `read-jobs` 与总结费用回执。相同请求重放返回已有记录，参数变化会拒绝；等待期间不按排队时长过期。

后台重启后，下次加载微信工作区会恢复尚未启动的条目。中断的执行任务保留“状态待核实”，阻止后续自动运行，避免重复计费。队列未结束时仍禁止清理、单张重试等冲突操作。远程入口保持只读。
