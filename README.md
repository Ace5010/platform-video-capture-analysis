# Observe 统一工作台

当前本机入口为 `http://localhost:3000/`，顶部包含“内容情报台”和“微信读取”。微信的聊天总结、完整讨论原文、成员与日期筛选、读取管理已接入同一前端与主机服务。原有视频功能继续保留，微信数据仅限本机访问。

启动继续使用 `scripts/launch.ps1`；旧微信快捷入口也转到此工作台。数据位置、依赖、总结规范与验证方式见 [微信模块接入说明](docs/observe-wechat-integration.md)。

## 内容情报台

本机作为数据主机运行的多设备内容监控工作台。当前只启用抖音，并为小红书、哔哩哔哩和 YouTube 保留入口。账号、视频元数据、互动快照、口播稿和 AI 分析保存在主机 SQLite；浏览视频按需在线传输，不在项目目录保存视频文件，不采集评论正文或播放量。

## 当前功能

- 监控账号数量不设产品上限，保存主页链接、名称和真实头像。同一抖音主页按 `/user/` 后的账号 ID 去重，分享来源参数或页面锚点不同也只保留一个账号；重复添加沿用已有名称、作品和分析，不重新建档。
- 首次建档抓取近 30 条非置顶视频；日常检查从最新普通作品持续读取到上次成功确认的作品边界或列表末尾，近期 5 条用于刷新互动数据。
- 添加账号时，保存账号与登记首次建档任务在同一后台事务中完成。读取期间可以继续添加，后台依次读取；信源管理可一次“抓取全部待建档账号”。排队、正在读取与失败分别展示，已入队或已建档账号不会重复提交，刷新或关闭网页不影响队列。
- 采集排队不会因等待超过 30 分钟而过期，单次浏览器采集仍保留执行时限。单个账号失败后继续下一项；明确的登录失效或验证码阻断会保留任务并暂停队列，处理后点击“已处理，继续读取”。暂停状态随后台重启保留，不自动无限重试。
- 所有账号逐个执行、按账号切换分析，并按账号 ID 与视频 ID 去重。
- 最新视频自动并入该账号的互动数据。
- 保存标题、正文文案、封面、原视频链接、发布时间、时长，以及点赞、评论、收藏、分享四项快照。
- 工作台保留四个主入口：内容浏览、链接分析、互动数据、信源管理。内容浏览合并原首页、最新视频与总数据里的重复视频列表；支持账号、全部内容/每账号最新 5 条、已有结果/尚无结果筛选。链接分析和链接记录仍独立保存。
- 互动数据直接展示当前账号的图表，默认以每条视频为节点、按发布时间从早到晚绘制折线，可切换柱形和点赞、评论、收藏、分享四项指标。缺失值断线，实际零值保留。按数据高低排序时自动切到柱形；切回折线恢复发布时间顺序。图表显示样本范围和采集时间，单条快照增量及账号基准继续保留；累计量不等于每日新增，也不是等发布时长比较。
- 首页按视频发布时间展示跨账号内容，支持账号筛选；发布时间、首次采集和互动快照时间分别显示，刚收录的旧视频不会冒充新发布内容。查看已有结果不会触发分析。按当前账号筛选时，“检查当前账号”只提交该账号；“检查全部账号”才逐个检查全部已建档账号。
- 视频列表在标题上方突出作者名，并显示对应账号已保存的粉丝量；标题下方只展示原视频简介，省略与标题重复的部分，不用口播稿或分析摘要补位。
- 点击视频标题打开大阅读层，列表日期后仅显示口播稿与分析状态，不放重复的阅读快捷按钮；进入阅读层后选择口播稿、视频内容分析或 Remotion 制作规范。阅读层提供 18 / 20 / 22 px 字号、复制、下载、原视频核对和当前列表内的上一条/下一条，支持 Esc 关闭并返回原入口和列表位置。切换和展开有过渡，尊重系统的减少动态效果设置，不触发模型请求。补全和重新分析仍在阅读层内主动发起。
- 悬停卡片即静音预览，点击封面打开可拖动、缩放的小窗并有声播放；未悬停也会立即开始取址和加载。已开始的悬停播放保留同一媒体元素与进度。小窗提供进度、音量、倍速和全屏控制，拖动标题栏移动位置，拖动四角调整大小；尺寸与位置受屏幕边界约束，关闭按钮与播放控制保持可操作。切换到其他作品时先中止旧媒体，再等待新作品的播放源。在线播放源同时校验画面与声音轨道，排除只有画面的地址；备用地址按低清优先排序。点击标题或正文只切换右侧阅读内容。同一时刻只有一个播放元素，离开、实际滚动、切换账号和页面隐藏会结束过期的悬停预览与上游传输；没有本地文件不再阻止播放，也不再显示“等待下载”。
- 左侧“全部账号”下方固定入口“新增检查视频”汇总最近 72 小时检查发现的新作品，按发现时间从新到旧排列，显示发现时间并保留原发布时间。只有用户主动“检查全部账号/检查当前账号”时新发现并成功入库的作品进入该分区；仅刷新互动快照、首次历史建档和链接分析都不会进入。可点击“清除”清掉当前列表的提醒，刷新或重复检查后也不会重新出现；清除期间或之后新发现的作品仍会展示。到期或手动清除都只退出该分区，作品、封面、口播稿、分析结果和费用记录继续保留在“全部账号”中。
- 点击账号后，工作区标题的账号名字右侧显示粉丝量（如“12.3万粉丝”或“粉丝 —”）；左侧切换选项只显示账号名字和作品数，长名字省略显示，避免换行与下一项重叠。粉丝量随首次建档、检查全部账号和检查当前账号刷新，来源仅为该账号自己的公开资料或主页资料区；平台只给缩写时标记为近似，不会伪造精确整数，读取失败也不会让已完成的视频采集回滚。
- 主动采集更新作品与互动数据，新入库的视频随后自动排队生成本地口播稿，不长期保存媒体。预览和粉丝读取不调用模型，采集与本地转写不要求 Qwen Key。只有主动点击“分析”或“补全分析”才执行付费云端分析（此时会临时获取完整视频）。已完成的分区独立保存和复用，生成完成不代表用户已阅读。
- 独立的“链接分析”分区支持粘贴抖音分享短链接、标准视频链接或整段分享文案；点击“开始分析”后解析视频 ID，页面立即开始准备站内在线播放，分析任务同时沿用完整视频、云端口播识别与 Qwen 链路。播放器旁可切换口播稿、视频内容分析和 Remotion 制作规范，已保存的结果随刷新显示，更新结果不重置播放；提交后不再自动弹出阅读窗口。历史结果永久保存并直接复用，切换链接记录也自动加载对应视频，但不会把博主加入监控账号，也不会混入账号视频数和互动数据。在线播放只使用受保护的按需预览接口，不保存本地视频。
- 如果抖音后台页未加载完整的封面和博主信息，采集组件会短暂激活视频标签页，读取后返回原标签页；如果你已主动切到其他标签页，则不会抢回焦点。已有完整分析可直接复用，无需 Qwen 配置或采集组件在线。
- 后续采集到的视频缺少口播稿时，自动用 `D:\AI\Qwen3-ASR-1.7B` 的本地模型顺序识别完整音轨，默认读取该目录的 `hotwords.json`。 同时使用 AI 领域上下文，优先提示当前标题、文案中的产品名、标签和模型版本，保留模型原始识别文字。采集时同步提取可用的目标媒体地址，交接给本地转写，避免重复打开视频页；地址只在主机内存保留最多 30 分钟、最多 512 条，缺失、失效或主机重启后再按需取址。转写独立排队、重启续跑，失败不会中断采集；完成后直接在“口播稿”查看。旧视频可点“提取口播稿”，失败可重试，已有口播直接复用。自动转写不调用云端、不产生 API 费用，不批量回填历史视频。可通过 `DOUYIN_LOCAL_ASR_DIR` 指定部署目录，`DOUYIN_AUTO_TRANSCRIBE=0` 关闭本地队列。
- 画面分析仍由用户主动触发，使用完整视频与已有口播；缺少口播时沿用云端 `qwen3-asr-flash-filetrans`。本地 `faster-whisper` 兼容入口和现有标点规范化保留，只处理标点，不改动识别文字。
- 每次 AI 分析（包括失败和重试）分别记录视频模型的 Token 用量和云端口播的音频时长用量，并保留请求标识与计价依据。已分析的视频直接显示本次估算金额，点开“用量与费用”即可查看输入/输出 Token、口播秒数、分项费用及历次记录，无需展开长篇分析。转写按秒计费，不能混入视频模型的 Token 费用；未收到完整用量时标记“待账单核对”，不会误报为 0 元。复用口播不会再次产生转写请求，免费额度、资源包和优惠后的实际扣款仍以百炼账单为准。
- 手机或其他电脑可登录同一网页，发起抓取与 AI 分析。实际采集由电脑后台控制的专用 Chrome 浏览器执行，电脑和手机均无需安装扩展。

## 在线播放与完整视频分析

浏览播放和 AI 分析是两件事，互不触发：

- 浏览播放按需传输。主机先用目标视频 ID 在专用浏览器里解析出一个平台已经提供、绑定该作品的低清源（首选短边约 480，360–540 档均可，同等可辨认时优先更低码率），在服务端内存里按上限预读开头少量字节，随后由网页原生播放器通过受保护的 `/api/previews/{videoId}/{generation}/media` 接口按范围取流，主机逐段转发并在观看结束时停止读取。内存缓存有总量上限和空闲淘汰，不建立磁盘媒体缓存。
- 播放候选优先选择平台已有的音画合一地址，再按低清偏好排序，避免先逐个验证音轨分离的 DASH 视频地址。选用前仍通过实际切片验证视频、音频轨道和范围读取。轨道索引按实际大小读取，默认最多 2 MiB 且不超过文件大小的 20%；未识别到索引时保留 512 KiB 小范围。验证后的前缀直接复用于播放，不重复取流。网页实际尝试解码，不凭笼统编码查询阻止播放。首次取址仍需要等待抖音页面，不能保证立即播放。
- 预览不下载整片、不调用模型、不创建分析任务；退出、切换和离开悬停都会取消不再需要的传输。没有低清源或源不支持范围读取时如实说明限制，不偷偷整片下载。
- 完整视频分析只在你主动点击“分析”或“补全分析”时运行，会临时获取该作品的完整视频，并在成功、失败或取消后清理临时媒体。

## 完整视频分析链路

1. 电脑专用浏览器打开被选视频的标准详情页，前后校验视频 ID，只接受已绑定到目标作品的抖音 HTTPS CDN 媒体源。分析目的优先选择约 1080p 的完整源，同分辨率选较高码率；没有合适源时选最接近的可用清晰度。网页状态不可读时，复用页面已收到的官方公开详情响应中的目标媒体信息，不将未确认归属的预加载资源视为成功。
2. 完整媒体只保存在分析任务的临时目录 `tmp/`；用 ffprobe 校验视频流及时长；若视频与音频是分离流，只使用 FFmpeg `-c copy` 做无损封装。
3. 同一视频已有完成的口播时直接复用；本地转写正在排队时优先等待，最多 120 秒。仍缺少口播时，从已校验的完整媒体中无损提取完整音轨，由云端 `qwen3-asr-flash-filetrans` 识别，与视频上传准备并行进行。画面分析始终使用完整视频，不额外转码压缩。
4. 默认复用微信模块已安装、已登录的 CodeBuddy，通过独立子进程将完整视频字节作为原生 `video_url` 输入交给 `minimax-m3`。明确模型额度耗尽后切换已通过完整视频验证的 `minimax-m3.1-flash`；账户额度、认证、网络或上下文错误不触发换模型。应用内嵌视频上限为 40 MiB，超过时按原有 FFmpeg stream copy 流程连续无损分段、逐段分析后整合，所有分段仍为完整媒体，工作台不自行抽关键帧。
   - CodeBuddy 官方 CLI 负责登录、请求目标和计费；仅在本次子进程中适配视频请求格式，不修改依赖或复制登录凭据。传输前核对完整文件哈希，模型未确认收到画面时不保存分析结果。GLM-5.3-Flash 在当前 CodeBuddy 通道的文件与视频直链实测均未收到画面，因此不自动切入。
   - 设置 `DOUYIN_ANALYSIS_PROVIDER=qwen` 可使用原有 Qwen 兼容流程；其完整视频上传、服务端采样预算和严格输出校验继续保留。
5. 口播完成后，将口播稿与完整视频交给模型，保留严格结构化输出校验。完整结束后分别校验内容分析与制作规范，合格分区先保存，缺失分区不会标记完成。断流、超时等提交状态不确定的付费请求不盲目重发。CodeBuddy 官方 Token、积分、实际模型和完整视频输入哈希保存在 SQLite，云端口播的时长及人民币费用单独记录。内容分析包括快速概览、具体信息、观点与依据、画面演示及适用范围和限制；制作规范保留工程、素材、镜头、视觉动效、字幕与验收步骤。
6. 成功、失败或取消后立即删除分析任务的临时媒体；SQLite 不保存视频二进制，也没有本地视频文件登记表。

工作台和数据库在本机。点击“AI 分析”后，完整音轨会发送给阿里云百炼进行云端转写，完整视频、标题、正文和口播稿会发送给云端视频模型；已有完成口播时跳过音轨转写。采集本身不会触发这些云端请求。

## 首次安装

需要 Node.js、Python 3 和 FFmpeg/ffprobe。然后在项目目录运行：

```powershell
npm install
npm run setup:asr
npm run dev
```

`setup:asr` 沿用现有安装流程，创建 Python 环境并安装本地兼容入口所需的识别与标点依赖。默认视频分析使用云端口播识别，不会触发 `large-v3` 模型下载；只有单独使用本地识别兼容入口时才需要该模型。

`npm run dev` 固定启动两个进程：

- 工作台：`http://localhost:3000`，监听局域网地址。
- 主机 API、SQLite 与任务队列：`http://127.0.0.1:43129/health`，同时监听局域网地址；保留本地 ASR 兼容接口。

端口固定是为了让浏览器安全来源、Cookie 和 API 白名单保持一致；若端口被占用，脚本会明确失败，不会静默跳到另一个端口。

第一次打开 `http://localhost:3000` 时，先设置至少 10 位的局域网访问密码。首次设置和 Qwen API Key 录入只能在主机的 localhost 页面操作。API Key 使用 Windows 当前用户 DPAPI 加密，文件位于：

```text
项目目录\data\host-service\qwen-secret.dpapi
```

它不会写进浏览器 localStorage、SQLite、Git 或请求日志。之后在页面的“配置 Qwen”中粘贴 Key 即可；没有 Key 时，采集和数据分析照常工作，只有视频 AI 分析按钮会被阻止。

## 专用浏览器（无需扩展）

桌面入口分为“Observe（本地）”和“Observe（在线）”。本地入口显示 PowerShell 启动状态，自动启动缺少的后台和网页服务，等待就绪后在 Chrome 打开 `http://localhost:3000`；服务已运行时直接复用。在线入口通过 Chrome 打开 `cloudflare-pages.json` 中的正式网站，不启动本机服务；远程使用仍需要主机后台与隧道运行。启动错误保留在命令行里，服务日志在 `outputs/launcher-host.*.log` 和 `outputs/launcher-web.*.log`。电脑重启后使用本地入口启动服务。如果项目搬家或桌面快捷方式不见了，在当前项目目录双击“恢复桌面快捷方式.cmd”即可恢复两个入口，旧入口备份在 `outputs/shortcut-backups/`；已经启用的开机启动项可在新目录重新执行原启用命令更新路径。

在电脑的 localhost 工作台点击“打开抖音登录窗口”，首次在新开的专用 Chrome 中登录抖音。之后任务会自动打开浏览器，登录状态保存在 `data/host-service/browser-profile/`，与日常 Chrome 资料分开；不复制个人浏览器 Cookie。

采集由 `host_service/browser.py` 消费现有 SQLite 队列，通过标准输入输出管道控制 `scripts/browser-worker.mjs`。Playwright Core 复用已安装的 Chrome，不下载额外浏览器、不开放远程调试端口。任务执行时复用 `chrome-extension/background.js` 内的目标校验与采集函数，但不加载扩展、不执行扩展后台连接逻辑；旧扩展的采集接口已停用，避免重复领取任务。

采集函数在每次任务开始时重新读取，因此修改采集逻辑后不需要刷新扩展。前端开发服务自动加载界面修改；修改 Python 后台或浏览器驱动进程时仍需重启电脑服务。桌面快捷方式继续使用。

仅在你主动发起时采集。关闭工作台网页不会中止已提交任务；电脑休眠或关机时无法继续。登录失效或出现验证码时，请在电脑专用浏览器里完成操作，再重试任务。

2. 确认当前网络是可信家庭/办公网络，并在 Windows 设置中把它设为“专用网络”。
3. 用管理员 PowerShell 在项目目录执行：

```powershell
.\scripts\allow-private-network.ps1
```

脚本只对“专用网络”的本地子网放行 TCP 3000 与 43129；若当前只有“公用网络”，它会拒绝修改。不要做路由器端口映射，也不要把这两个端口暴露到互联网。

4. 手机或另一台电脑在同一局域网打开终端给出的地址，用主机设置的访问密码登录。它们可以发起首次建档、最新检查和 AI 分析，但电脑和服务必须保持运行，采集浏览器会按需自动启动。

## Cloudflare 远程访问（无需自有域名）

公网网页部署在 Cloudflare Workers；电脑仍负责 SQLite、专用 Chrome 和视频分析。手机通过同一网站的 `/host/` HTTPS 接口访问后台，不能直接请求公网地址的 `43129` 端口。公网入口继续使用电脑上设置的工作台访问密码，不需要手机 VPN 或扩展；电脑必须开机、联网且不休眠。

`npm run build` 会在构建时预渲染匿名首页，并由 `postbuild` 校验版本、发布到静态资源目录，打开网页时无需再次执行 React 服务端渲染。`cloudflare-worker.ts` 将 `/host/*` 直接交给原有受限网关，避免历史数据响应经过页面框架处理而耗尽免费套餐每请求 10ms 的 CPU 额度（1102）。账号、口播稿和分析结果仍在登录后实时获取，接口保持 `no-store`；不能把这些数据写进静态首页。新增依赖请求状态的首页逻辑时，须重新评估预渲染边界。Cloudflare 构建命令继续使用 `npm run build`，部署命令不变。

连接方式为 `手机 → Workers → VPC Service → Cloudflare Tunnel → 电脑受限接口`。Workers VPC 在公开测试期间免费，仍受 Workers 套餐的请求和计算额度限制，不能承诺永久免费。它需要电脑能通过 UDP 7844 连接 Cloudflare（QUIC）；能打开网页不等于隧道已经连通。不同运营商和网络的实际可达性需另行验证。

### 一次性配置

1. 在 Cloudflare 的 Tunnels 创建本项目专用隧道，例如 `content-workbench-home`。无需添加公共域名或创建公网应用路由。
2. 在电脑项目目录运行 `powershell -ExecutionPolicy Bypass -File scripts/install-cloudflared.ps1`。脚本只下载官方 Windows 64 位版本并验证 SHA-256，存入被 Git 忽略的 `data/tools/`，不会安装全局服务或修改防火墙。
3. 在本机终端运行 `.venv\Scripts\python.exe scripts/configure-remote-host.py`，按提示粘贴该隧道的 token。输入不回显，凭据保存在独立的 Windows CurrentUser DPAPI 文件 `data/host-service/remote-connection.dpapi`。不要把 token 放进源码、命令行参数、聊天或普通日志。
4. 在 Workers VPC 创建 **HTTP Service**：选择该隧道，目标 IPv4 填 `127.0.0.1`，HTTP 端口填 **43130**。不要绑定 `43129`，它保留了本机管理功能。把返回的 Service ID 填入 `cloudflare-host.json` 的 `vpcServiceId`；其中账号 ID、正式网站来源和 Service ID 都是非秘密配置。
5. 保存并推送配置后，现有 GitHub 自动构建会部署 VPC 绑定。构建命令为 `npm run build`，部署命令为 `npx wrangler deploy --config dist/server/wrangler.json`。VPC 是账号内私有服务绑定，不提供可绕过 Worker 的公网后台网址，也不需要另建一套网页登录凭据。
6. 确认电脑没有进行中的任务后重启主机后台。它会启动仅监听 `127.0.0.1:43130` 的远程入口，并以当前 Windows 用户启动 cloudflared；之后仍使用现有桌面快捷方式。隧道进程由后台管理，退出后台时一起停止，不安装额外开机服务。

### 权限和验收

- 原有网页 `3000`、主机 `43129` 和兼容 ASR `43128` 端口不变；`43130` 仅监听回环地址，接收私有 VPC 隧道转发，并验证正式网站来源、工作台密码会话和 CSRF。不能做路由器端口映射，也不要放行其公网或局域网入站。
- 远程访问始终按非本机处理，即使隧道连接来自 `127.0.0.1`。首次设密码、API Key 配置、旧数据迁移、打开抖音登录窗口和旧扩展接口均禁止远程调用。普通读取、登录、人工提交采集/分析及取消任务复用现有 API、SQLite 和 CSRF 检查。
- 浏览器只持有原有 HttpOnly 会话，公网会话带 `Secure; SameSite=Strict`。Worker 不透传其他 Cookie 或客户端伪造的内部凭据，限制接口和请求体大小，不缓存用户数据，不在连接超时后自动重发任务。
- Cloudflare 隧道健康后，手机在关闭 VPN 的移动网络下打开正式网址并登录，检查已有分析、手动采集和重连。模型分析仍由主动点击触发并按百炼规则计费；常规连接验收不用真实付费模型。
- 关机或休眠后后台无法提供数据或执行任务；重新联网启动后再连接。云端没有复制一份数据库，已有结果仍留在电脑中。连接失败不会清空历史数据。
- 隧道异常的最近记录在 `data/host-service/remote-tunnel.log`，内容经过脱敏并限制大小。远程通道配置失败不会阻止原有本机服务启动。开发模式继续直连本机后台，不要求 Cloudflare 登录。
- 后台持续管理隧道：异常退出后按 1、2、5、10、15、30 秒的间隔重新启动，持续故障时最长每 30 秒尝试一次；连续健康运行 1 分钟后恢复初始间隔。每 2 秒检查本项目客户端的 `/ready`，短时断网先交给客户端重连，已连接的通道连续 10 秒没有可用连接就重新选择网卡和接入节点（首次建立连接最多等待 30 秒）。检查使用独立的随机回环端口，不开放网络入口、不提交采集或模型任务；视频抓取的三次上限不变。正常关闭后台后停止重连，缺少客户端或权限错误会明确停止并提示处理。
- 本机 `/health` 额外提供通道状态，公网和局域网请求不返回这些诊断字段。桌面启动器在本机就绪后立即打开网页，并在命令行显示当前通道状态；通道未连接时保留提示，不把已可用的本机工作台当作启动失败。开机后台启动会等待通道状态后给出提示。本机就绪不代表远程访问成功，此检查不能代替公网网页和手机实际访问验收。
- 希望打开网站即可使用时，可运行 `powershell -ExecutionPolicy Bypass -File scripts/create-desktop-shortcut.ps1 -EnableAutoStart`，将现有启动器加入当前用户的 Windows 登录启动项，提前运行后台和远程通道，不弹浏览器、不自动采集或分析。使用 `-DisableAutoStart` 可关闭；它不会注册管理员服务或修改 VPN、睡眠设置。未登录 Windows、电脑关机或休眠时仍不可用。桌面启动器在本机就绪后立即打开网页，通道检查在之后进行；公网网页遇到连接失败会自动重新读取登录状态，恢复后直接加载内容，不自动重发任务。
- Windows 上，隧道会读取已联网实体网卡的 IPv4 地址，并仅为 cloudflared 绑定该出口；通过 Cloudflare 官方接入域名的 A 记录选择节点，兼容拒绝 SRV 查询或无法承载 QUIC 的 TUN 代理。不会关闭 VPN，也不会修改系统 DNS、路由或代理设置。没有合适实体网卡或查询超时则保留客户端默认连接方式。该兼容路径使用官方客户端的 `--edge` 诊断参数，已验证版本为 `2026.9.1`；升级客户端后应复测。TLS 证书校验、QUIC、私有 VPC 和访问密码均保留。

官方参考：[Workers VPC 配置](https://developers.cloudflare.com/workers-vpc/get-started/)、[Tunnel 与 QUIC 要求](https://developers.cloudflare.com/workers-vpc/configuration/tunnel/)、[公开测试期价格](https://developers.cloudflare.com/workers-vpc/platform/pricing/)。

## 数据与隐私

- 主数据默认保存在项目目录下的 `data\host-service\monitor.sqlite3`（WAL 模式）。可通过 `DOUYIN_HOST_DATA_DIR` 或 `DOUYIN_DATA_DIR` 环境变量覆盖整个运行数据目录。
- 旧版 localStorage 首次迁移前会创建本地 JSON 备份，迁移校验成功后才标记完成。
- 各设备通过带 CSRF 的密码会话访问主机；专用浏览器驱动只使用本机进程管道。签名 CDN URL 不写入浏览器持久存储或日志。
- 采集任务离线等待 30 分钟后过期；AI 视频分析任务会保留 7 天，避免因 Chrome 临时断开而丢失已提交的分析请求。领取中的任务采用短租约并持续续期，驱动进程断线或重启后会自动回到队列；采集结果事件具有幂等 ID，重复提交不会生成重复视频或快照。
- 采集器只处理公开页面数据。页面返回空列表、跳转到其他账号/视频或字段不完整时会失败，不会写入半成品或伪造数据。

工作台已运行时，`node scripts/test-discovery-clear-browser.mjs` 使用隔离 Chrome 和模拟主机请求验证“清除”的刷新保持、数据保留、新发现并发、失败重试、超过 500 条时的完整清除和手机宽度；不会修改真实数据库或提交采集、分析任务。

账号身份和合并回归可单独运行 `npm run test:accounts`；前端运行时用 `node scripts/test-account-identity-browser.mjs` 检查重复添加、后台复用与新账号抓取，用 `node scripts/test-account-queue-browser.mjs` 检查读取期间添加、一次补建档和刷新后的排队状态，所有主机请求均被隔离拦截。`npm run test:host` 包含原子保存、并发去重、顺序执行、长时间等待、失败继续与登录暂停恢复的隔离回归。历史重复记录只能在无活动任务、停止后台服务后显式处理：`scripts/merge-duplicate-accounts.py KEEP_ID DUPLICATE_ID` 默认只检查，增加 `--apply` 才会先做 SQLite 备份再合并，并逐表核对作品、互动、分析和任务历史；不能直接删除重复账号代替合并。

浏览器界面验收可在前端 `3000` 端口已运行时执行 `node scripts/preview-workspace-fixture.mjs`，打开终端输出的本机随机端口地址。该页面使用模拟账号、缺失指标及完整/部分分析结果，拦截主机接口和写请求，不执行真实采集或付费分析；生产数据库和当前工作台登录状态不参与测试。验收后用 Ctrl+C 关闭此模拟服务。

按需播放的完整链路（解析低清源、内存预热、Range 转发、停止读取）由 `node scripts/test-playback-browser.mjs` 用本地测试媒体在真实 Chrome 中验收，不需要访问抖音。要在**已运行的工作台**上检查“新增检查视频”入口、粉丝量展示、卡片点击分工和悬停/离开行为，可执行 `node scripts/test-live-workspace.mjs`；它只读页面并创建一个临时会话，不发起采集或分析。

真实播放验收可执行 `node scripts/test-live-playback.mjs <当前列表的视频ID>`，检查悬停、连续播放、实际解码的非零音频信号、小窗拖动、全屏、进度跳转、关闭后停止传输及不落盘。设置 `PLAYBACK_DIRECT_OPEN=1` 验证指针留在封面外、键盘直接打开后独立加载；设置 `PLAYBACK_EXPECT_COLD=1` 要求源原先为 `idle`，`PLAYBACK_FEED=discoveries` 选择新增检查分区。脚本读取真实抖音媒体并创建临时会话，不提交采集或付费分析任务。

默认使用无头 Chrome；在 PowerShell 中先设置 `$env:PLAYBACK_HEADLESS='0'` 可验收有窗口的 Chrome。测试分别记录取址、轨道识别、媒体首字节和实际开始播放的耗时，不能用“地址已准备”代替首帧。

冷启动验收可设置 `$env:PLAYBACK_BASE_URL='http://127.0.0.1:3000'` 对齐实际访问入口，以及 `$env:PLAYBACK_EXPECT_COLD='1'` 强制要求目标源在悬停前为 `idle`；已准备过的作品会直接使测试失败。`$env:PLAYBACK_FROM_ROW_INDEX='0'` 先播放第一条，再移入目标作品，检查切换；每次脚本运行都使用独立浏览器缓存。有窗口测试可设置 `$env:PLAYBACK_KEEP_HOVER='1'`，持续向同一卡片坐标发送鼠标移动，避免 Windows 窗口通知把 CDP 模拟位置恢复成实体鼠标的旧坐标。该设置仅属于测试，不改变网页的离开即停止行为，也不提前取址。

播放直接交给浏览器解码实际媒体，不根据笼统的编码名称预先拒绝。悬停准备期间保留封面，取得可显示的视频帧后才覆盖封面。遇到阻断原有播放行为的问题，应先反馈给用户并确认处理方案，不擅自替换为原站跳转或在界面堆放技术报错。

取址优先复用原站已提供、绑定目标视频 ID 的媒体信息；信息稍晚到达时，在播放器激活期间继续读取，不要求原站先成功解码。主机根据 MP4 前置轨道表控制识别读取量，并将选中源已验证的前缀直接存入有总量上限的内存缓存。播放请求立即复用已有字节，准备和播放都不保存整片本地视频。

预览不再套用完整分析流程的播放器就绪等待；专用 Chrome 使用后台标签页并复用窗口，不因每条取址弹出窗口。媒体校验的单次连接/读取及轨道解析时限为 5 秒，超时继续尝试平台已有且已绑定同一目标的候选；连续播放仍沿用原有时限。受保护状态接口保留各候选的阶段、耗时和错误类型，排除媒体地址，不在页面显示这些诊断。播放版本失效时同一悬停只重新准备一次，失败后允许下一次移入重试，避免一直留在旧地址。

鼠标进入整条视频卡片后立即取址、加载并静音播放，不再等待悬停延迟，不提前准备列表视频。封面上的“正在加载”持续到第一帧可播放；实际滚动取消预览，滚动完成后晚到达的旧事件不会取消新悬停。缓存仅保存在后台内存：默认总量 32 MiB、闲置 15 分钟淘汰，每个源保留最多 2 MiB 开头、2 MiB 最近播放片段和 64 KiB 已读取的末尾元数据。离开后中止播放器取流，已收到的缓存可供下次复用。首次平台取址与读取仍有网络等待，不能把缓存命中速度当作首次播放速度。

正常 `/api/state` 读取保留完整作品与链接分析历史；仅显式指定 `?videos=N` 时返回数量受限的窗口（最多 2000 条），该窗口不代表完整账号历史。网页继续使用完整读取，账号切换、图表及 72 小时新增分区不会受到默认 600 条截断。

## Remotion 制作方案

新发起的 AI 解析使用经过目标校验的完整视频，优先选 1080p 媒体源，并使用独立云端转写的口播稿，输出工程设置、素材清单、逐镜头时间线、视觉规范、动效转场、字幕音轨对齐、制作验收步骤和待确认项。结果可下载为 Markdown，交给 Remotion 制作者使用；本工具不生成或渲染 Remotion 工程。浏览用的低清在线播放不参与这条链路，也不会被当作分析素材。

历史内容分析仍保留。补全仅针对已经启动过分析、且实际缺少分区的历史视频，不覆盖从未分析的视频，也不因输出结构更新就重跑已有有效内容。旧版内容以原文或已有摘要整理展示，未区分的证据与推断不冒充已经核实；确实缺失的分区才使用完整视频补齐。已有完整口播直接复用。视频模型通过独立云端转写获得口播文字；口播稿不能当作逐字对齐数据，音效、配乐和精确对齐仍须在制作时核对。模型采样画面中的估计参数不能当成逐帧测量或原作者真实制作过程。

制作规范参考 Remotion 官方文档：[工程基础](https://www.remotion.dev/docs/the-fundamentals)、[Sequence 时间线](https://www.remotion.dev/docs/sequence)、[帧驱动动画](https://www.remotion.dev/docs/animating-properties)、[渲染](https://www.remotion.dev/docs/render)。

### 三个阅读分区

“口播稿”保留完整转写；“视频内容分析”先充分讲清作者的主要内容，包括重要观点、必要解释、关键例子、条件和结论，再在下方补充具体信息、操作测试与画面结果。篇幅随实际信息量变化，不限制为固定句数、段数或字数；信息少则简短，信息多则充分展开。“Remotion 制作规范”单独回答视频如何呈现及制作时如何参考。普通详情默认进入内容分析，三个分区都能在页面内完整阅读、复制和下载，切换分区与字号不会发起分析。尚未分析时明确显示缺失，不根据标题编造摘要。

内容分析继续兼容现有五字段结构：主要内容必填，四个补充字段仍须是字符串，但没有相应信息时允许为空，页面不显示空栏目，也不将其判为待付费补全。来源和重要限制用自然语言说明，避免反复堆叠证据标签。旧版保存文字原样保留，新规则不会自动改写历史结果或触发模型重跑。

提示气泡支持点击关闭，也保留自动消失。日常检查按上次成功采集的作品 ID 边界停止；近期作品继续更新互动快照，按视频 ID 去重。

## 完整抓取与自动恢复

视频分析任务由主机统一管理完整视频获取的三次总尝试（首次加两次重试）。每次重新获取同一目标的媒体地址、下载并校验，逐步增加等待间隔，并设置单次时限。前两次失败仍保持处理中并显示“正在重新获取视频，尝试 2/3”或“尝试 3/3”；确认删除、无权限或必须重新登录时提前停止。任务可以取消，取消后不会继续安排尝试。

取得有效视频后，后续步骤在任务内复用临时媒体。云端口播使用异步任务查询的有限恢复，不因查询失败重复提交；视频模型超时且无法确认执行状态时保留诊断与用量，交由用户核对。结果保存使用独立有限重试，不重新生成。若 SQLite 暂时无法保存，已返回的文字和用量在本机 `pending-analysis-results/` 保留以便恢复写入，不保留媒体或凭据。任务最终成功、失败或取消后仍按原规则清理临时媒体。

最终错误显示失败阶段、实际尝试次数、最后错误、已保留分区和必要操作。“复制诊断信息”提供任务/视频标识、各次实际错误和版本，排除 Cookie、密钥、令牌和签名地址。历史已保存内容不会因为新的获取任务失败而被清空。

一次检查中，详情页文字先加载而媒体未就绪时，程序会激活已校验的视频并等待实际字段齐全；仍有异常时最多重新尝试 3 次。只有账号本轮全部视频的必要字段通过校验，才写入并显示“已完成抓取”。不完整结果不会作为成功提交，也不会把未知互动数记为零。旧版本留下的待处理视频会在当前检查中一并恢复，按视频 ID 去重。不可恢复的阻断仍如实记录失败原因。
