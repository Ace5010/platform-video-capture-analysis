# 内容情报台

本机作为数据主机运行的多设备内容监控工作台。当前只启用抖音，并为小红书、哔哩哔哩和 YouTube 保留入口。账号、视频元数据、互动快照、口播稿和 AI 分析永久保存在主机 SQLite；不保存完整视频，也不采集评论正文或播放量。

## 当前功能

- 监控账号数量不设产品上限，保存主页链接、名称和真实头像。
- 首次建档抓取近 30 条非置顶视频；日常仅在用户主动发起时检查最新 5 条非置顶视频。
- 所有账号逐个执行、按账号切换分析，并按账号 ID 与视频 ID 去重。
- 最新视频自动并入该账号的互动数据。
- 保存标题、正文文案、封面、原视频链接、发布时间、时长，以及点赞、评论、收藏、分享四项快照。
- 工作台保留四个主入口：内容浏览、链接分析、互动数据、信源管理。内容浏览合并原首页、最新视频与总数据里的重复视频列表；支持账号、全部内容/每账号最新 5 条、已有结果/尚无结果筛选。链接分析和链接记录仍独立保存。
- 互动数据直接展示当前账号的图表，默认以每条视频为节点、按发布时间从早到晚绘制折线，可切换柱形和点赞、评论、收藏、分享四项指标。缺失值断线，实际零值保留。按数据高低排序时自动切到柱形；切回折线恢复发布时间顺序。图表显示样本范围和采集时间，单条快照增量及账号基准继续保留；累计量不等于每日新增，也不是等发布时长比较。
- 首页按视频发布时间展示跨账号内容，支持账号筛选；发布时间、首次采集和互动快照时间分别显示，刚收录的旧视频不会冒充新发布内容。查看已有结果不会触发分析。按当前账号筛选时，“检查当前账号”只提交该账号；“检查全部账号”才逐个检查全部已建档账号。
- 已有分析统一从“展开阅读”打开大阅读层，视频卡片不再提供“更多”菜单；进入阅读层后选择口播稿、视频内容分析或 Remotion 制作规范。阅读层提供 18 / 20 / 22 px 字号、复制、下载、原视频核对和当前列表内的上一条/下一条，支持 Esc 关闭并返回原入口和列表位置。切换和展开有过渡，尊重系统的减少动态效果设置，不触发模型请求。补全和重新分析仍在阅读层内主动发起。
- 只有主动点击“分析”或“补全分析”才临时获取完整视频，优先使用已有的 1080p 媒体源，一次任务覆盖口播稿、视频内容分析和 Remotion 制作规范；首次 30 条和日常采集不会自动消耗 AI。已完成的分区独立保存和复用，生成完成不代表用户已阅读。
- 独立的“链接分析”分区支持粘贴抖音分享短链接、标准视频链接或整段分享文案；提交后立即解析视频 ID，读取封面、标题和博主公开信息，并复用同一套完整视频、云端口播识别与 Qwen 分析链路。历史结果永久保存，但不会把博主加入监控账号，也不会混入账号视频数和互动数据。
- 如果抖音后台页未加载完整的封面和博主信息，采集组件会短暂激活视频标签页，读取后返回原标签页；如果你已主动切到其他标签页，则不会抢回焦点。已有完整分析可直接复用，无需 Qwen 配置或采集组件在线。
- 口播稿由云端 `qwen3-asr-flash-filetrans` 识别目标视频的完整音轨。已有完成的同视频口播稿直接复用，避免重复转写；本地 `faster-whisper` 仅保留兼容入口，不再用于视频分析的默认流程，也不作为云端失败后的自动回退。现有标点规范化继续保留，只处理标点，不改动识别文字。
- 每次 AI 分析（包括失败和重试）分别记录视频模型的 Token 用量和云端口播的音频时长用量，并保留请求标识与计价依据。已分析的视频直接显示本次估算金额，点开“用量与费用”即可查看输入/输出 Token、口播秒数、分项费用及历次记录，无需展开长篇分析。转写按秒计费，不能混入视频模型的 Token 费用；未收到完整用量时标记“待账单核对”，不会误报为 0 元。复用口播不会再次产生转写请求，免费额度、资源包和优惠后的实际扣款仍以百炼账单为准。
- 手机或其他电脑可登录同一网页，发起抓取与 AI 分析。实际采集由电脑后台控制的专用 Chrome 浏览器执行，电脑和手机均无需安装扩展。

## 完整视频分析链路

1. 电脑专用浏览器打开被选视频的标准详情页，前后校验视频 ID，只接受已绑定到目标作品的抖音 HTTPS CDN 媒体源。优先选择约 1080p 的完整源，同分辨率选较高码率；没有合适源时选最接近的可用清晰度。网页状态不可读时，复用页面已收到的官方公开详情响应中的目标媒体信息，不将未确认归属的预加载资源视为成功。
2. 主机默认把媒体临时下载到项目目录下的 `data\host-service\tmp`，用 ffprobe 校验它确实包含视频流，并核对下载时长与目标页面时长。若视频与音频是分离流，只使用 FFmpeg `-c copy` 做无损封装。
3. 从已校验的完整媒体中无损提取完整音轨，交给独立的云端 `qwen3-asr-flash-filetrans` 生成口播稿；云端转写与视频上传准备并行进行。同一视频已有完成的口播时直接复用，不重复上传音轨或转写。默认分析不再调用本机 CPU 口播识别。不会用关键帧、OCR 或仅口播稿代替完整视频，也不额外转码压缩。
4. 不超过 7 MiB 的完整文件直接以 Data URI 发送（为 Base64 编码后的 10 MB 限制预留空间）；更大的文件会使用百炼官方临时上传凭证原样上传，再把临时 `oss://` 引用交给 `qwen3.8-flash`。如果超过单文件或模型视觉预算，只做按时间连续的无损分段，所有分段仍会完整分析。
   - 工作台不自行抽关键帧。Qwen 接收完整视频，服务端采样默认最高 1 fps、单帧按 720p 级别像素预算、全片约 240 帧预算；长片按时长调整采样，控制视觉 Token 与等待时间。显式配置的采样频率仍受总预算约束。
5. 口播完成后，将口播稿与完整视频交给 `qwen3.8-flash`，保留严格结构化输出校验。视频模型使用流式返回，并限制思考预算；完整结束后分别校验内容分析与制作规范，合格分区先保存，缺失分区不会标记完成。断流、超时等提交状态不确定的付费请求不盲目重发。内容分析包括快速概览、具体信息、观点与依据、画面演示及适用范围和限制，区分作者说法、实际展示、AI 推断和未核实信息；制作规范保留工程、素材、镜头、视觉动效、字幕与验收步骤。实测参数与复现建议分开标注，不凭画面猜测原音轨。
6. 成功或失败后立即删除本机临时媒体；SQLite 只保留口播稿、结构化分析、来源哈希与状态。

工作台和数据库在本机。点击“AI 分析”后，完整音轨会发送给阿里云百炼进行云端转写，完整视频、标题、正文和口播稿会发送给云端视频模型；已有完成口播时跳过音轨转写。采集本身不会触发这些云端请求。

## 首次安装

需要 Node.js、Python 3 和 FFmpeg/ffprobe。然后在项目目录运行：

```powershell
npm install
npm run setup:asr
npm run dev
```

`setup:asr` 沿用现有安装流程，创建 Python 环境并安装本地兼容入口所需的识别与标点依赖。默认视频分析使用云端口播识别，不会触发 `large-v3` 模型下载；只有单独使用本地识别兼容入口时才需要该模型。

`npm run dev` 固定启动两个进程：

- 工作台：`http://localhost:3000`，监听局域网地址。
- 主机 API、SQLite 与任务队列：`http://127.0.0.1:43129/health`，同时监听局域网地址；保留本地 ASR 兼容接口。

端口固定是为了让浏览器安全来源、Cookie 和 API 白名单保持一致；若端口被占用，脚本会明确失败，不会静默跳到另一个端口。

第一次打开 `http://localhost:3000` 时，先设置至少 10 位的局域网访问密码。首次设置和 Qwen API Key 录入只能在主机的 localhost 页面操作。API Key 使用 Windows 当前用户 DPAPI 加密，文件位于：

```text
项目目录\data\host-service\qwen-secret.dpapi
```

它不会写进浏览器 localStorage、SQLite、Git 或请求日志。之后在页面的“配置 Qwen”中粘贴 Key 即可；没有 Key 时，采集和数据分析照常工作，只有视频 AI 分析按钮会被阻止。

## 专用浏览器（无需扩展）

双击桌面“信源抓取与分析”快捷方式，会自动启动缺少的后台和网页服务，等待就绪后打开 Chrome。服务已经运行时会直接打开网页，不重复启动服务。电脑重启后也使用这个快捷方式；只打开网页收藏不能启动本机服务。如果桌面快捷方式不见了，双击项目目录的“恢复桌面快捷方式.cmd”即可恢复。

在电脑的 localhost 工作台点击“打开抖音登录窗口”，首次在新开的专用 Chrome 中登录抖音。之后任务会自动打开浏览器，登录状态保存在 `data/host-service/browser-profile/`，与日常 Chrome 资料分开；不复制个人浏览器 Cookie。

采集由 `host_service/browser.py` 消费现有 SQLite 队列，通过标准输入输出管道控制 `scripts/browser-worker.mjs`。Playwright Core 复用已安装的 Chrome，不下载额外浏览器、不开放远程调试端口。任务执行时复用 `chrome-extension/background.js` 内的目标校验与采集函数，但不加载扩展、不执行扩展后台连接逻辑；旧扩展的采集接口已停用，避免重复领取任务。

采集函数在每次任务开始时重新读取，因此修改采集逻辑后不需要刷新扩展。前端开发服务自动加载界面修改；修改 Python 后台或浏览器驱动进程时仍需重启电脑服务。桌面快捷方式继续使用。

仅在你主动发起时采集。关闭工作台网页不会中止已提交任务；电脑休眠或关机时无法继续。登录失效或出现验证码时，请在电脑专用浏览器里完成操作，再重试任务。

## 其他设备访问

1. 双击电脑桌面快捷方式，在工作台展开“设置 → 手机访问地址”，并连接同一个 Wi-Fi。
2. 确认当前网络是可信家庭/办公网络，并在 Windows 设置中把它设为“专用网络”。
3. 用管理员 PowerShell 在项目目录执行：

```powershell
.\scripts\allow-private-network.ps1
```

脚本只对“专用网络”的本地子网放行 TCP 3000 与 43129；若当前只有“公用网络”，它会拒绝修改。不要做路由器端口映射，也不要把这两个端口暴露到互联网。

4. 手机或另一台电脑在同一局域网打开终端给出的地址，用主机设置的访问密码登录。它们可以发起首次建档、最新检查和 AI 分析，但电脑和服务必须保持运行，采集浏览器会按需自动启动。

## Cloudflare 远程访问（无需自有域名）

公网网页部署在 Cloudflare Workers；电脑仍负责 SQLite、专用 Chrome 和视频分析。手机通过同一网站的 `/host/` HTTPS 接口访问后台，不能直接请求公网地址的 `43129` 端口。公网入口继续使用电脑上设置的工作台访问密码，不需要手机 VPN 或扩展；电脑必须开机、联网且不休眠。

连接方式为 `手机 → Workers → VPC Service → Cloudflare Tunnel → 电脑受限接口`。Workers VPC 在公开测试期间免费，仍受 Workers 套餐的请求和计算额度限制，不能承诺永久免费。它需要电脑能通过 UDP 7844 连接 Cloudflare（QUIC）；能打开网页不等于隧道已经连通。不同运营商和网络的实际可达性需另行验证。

### 一次性配置

1. 在 Cloudflare 的 Tunnels 创建本项目专用隧道，例如 `content-workbench-home`。无需添加公共域名或创建公网应用路由。
2. 在电脑项目目录运行 `powershell -ExecutionPolicy Bypass -File scripts/install-cloudflared.ps1`。脚本只下载官方 Windows 64 位版本并验证 SHA-256，存入被 Git 忽略的 `data/tools/`，不会安装全局服务或修改防火墙。
3. 在本机终端运行 `.venv\Scripts\python.exe scripts/configure-remote-host.py`，按提示粘贴该隧道的 token。输入不回显，凭据保存在独立的 Windows CurrentUser DPAPI 文件 `data/host-service/remote-connection.dpapi`。不要把 token 放进源码、命令行参数、聊天或普通日志。
4. 在 Workers VPC 创建 **HTTP Service**：选择该隧道，目标 IPv4 填 `127.0.0.1`，HTTP 端口填 **43130**。不要绑定 `43129`，它保留了本机管理功能。把返回的 Service ID 填入 `cloudflare-host.json` 的 `vpcServiceId`；其中账号 ID、正式网站来源和 Service ID 都是非秘密配置。
5. 保存并推送配置后，现有 GitHub 自动构建会部署 VPC 绑定。构建命令为 `npm run build`，部署命令为 `npx wrangler deploy --config dist/server/wrangler.json`。VPC 是账号内私有服务绑定，不提供可绕过 Worker 的公网后台网址，也不需要另建一套网页登录凭据。
6. 确认电脑没有进行中的任务后重启主机后台。它会启动仅监听 `127.0.0.1:43130` 的远程入口，并以当前 Windows 用户启动 cloudflared；之后仍使用现有桌面快捷方式。隧道进程由后台管理，退出后台时一起停止，不安装额外开机服务。

### 权限和验收

- 原有网页 `3000`、主机 `43129` 和兼容 ASR `43128` 端口不变；`43130` 仅监听回环地址，接收私有 VPC 隧道转发，并验证正式网站来源、工作台密码会话和 CSRF。不能做路由器端口映射，也不要放行其公网或局域网入站。
- 远程访问始终按非本机处理，即使隧道连接来自 `127.0.0.1`。首次设密码、API Key 配置、旧数据迁移、打开抖音登录窗口和旧扩展接口均禁止远程调用。普通读取、登录、人工提交采集/分析及取消任务复用现有 API、SQLite 和 CSRF 检查。
- 浏览器只持有原有 HttpOnly 会话，公网会话带 `Secure; SameSite=Strict`。Worker 不透传其他 Cookie 或客户端伪造的内部凭据，限制接口和请求体大小，不缓存用户数据，不在连接超时后自动重发任务。
- Cloudflare 隧道健康后，手机在关闭 VPN 的移动网络下打开正式网址并登录，检查已有分析、手动采集和重连。模型分析仍由主动点击触发并按百炼规则计费；常规连接验收不用真实付费模型。
- 关机或休眠后后台无法提供数据或执行任务；重新联网启动后再连接。云端没有复制一份数据库，已有结果仍留在电脑中。连接失败不会清空历史数据。
- 隧道异常的最近记录在 `data/host-service/remote-tunnel.log`，内容经过脱敏并限制大小。远程通道配置失败不会阻止原有本机服务启动。开发模式继续直连本机后台，不要求 Cloudflare 登录。
- Windows 上，隧道会读取已联网实体网卡的 IPv4 地址，并仅为 cloudflared 绑定该出口；通过 Cloudflare 官方接入域名的 A 记录选择节点，兼容拒绝 SRV 查询或无法承载 QUIC 的 TUN 代理。不会关闭 VPN，也不会修改系统 DNS、路由或代理设置。没有合适实体网卡或查询超时则保留客户端默认连接方式。该兼容路径使用官方客户端的 `--edge` 诊断参数，已验证版本为 `2026.9.1`；升级客户端后应复测。TLS 证书校验、QUIC、私有 VPC 和访问密码均保留。

官方参考：[Workers VPC 配置](https://developers.cloudflare.com/workers-vpc/get-started/)、[Tunnel 与 QUIC 要求](https://developers.cloudflare.com/workers-vpc/configuration/tunnel/)、[公开测试期价格](https://developers.cloudflare.com/workers-vpc/platform/pricing/)。

## 数据与隐私

- 主数据默认保存在项目目录下的 `data\host-service\monitor.sqlite3`（WAL 模式）。可通过 `DOUYIN_HOST_DATA_DIR` 或 `DOUYIN_DATA_DIR` 环境变量覆盖整个运行数据目录。
- 旧版 localStorage 首次迁移前会创建本地 JSON 备份，迁移校验成功后才标记完成。
- 各设备通过带 CSRF 的密码会话访问主机；专用浏览器驱动只使用本机进程管道。签名 CDN URL 不写入浏览器持久存储或日志。
- 采集任务离线等待 30 分钟后过期；AI 视频分析任务会保留 7 天，避免因 Chrome 临时断开而丢失已提交的分析请求。领取中的任务采用短租约并持续续期，驱动进程断线或重启后会自动回到队列；采集结果事件具有幂等 ID，重复提交不会生成重复视频或快照。
- 采集器只处理公开页面数据。页面返回空列表、跳转到其他账号/视频或字段不完整时会失败，不会写入半成品或伪造数据。

## Remotion 制作方案

新发起的 AI 解析使用经过目标校验的完整视频，优先选 1080p 媒体源，并使用独立云端转写的口播稿，输出工程设置、素材清单、逐镜头时间线、视觉规范、动效转场、字幕音轨对齐、制作验收步骤和待确认项。结果可下载为 Markdown，交给 Remotion 制作者使用；本工具不生成或渲染 Remotion 工程。

历史内容分析仍保留。补全仅针对已经启动过分析、且实际缺少分区的历史视频，不覆盖从未分析的视频，也不因输出结构更新就重跑已有有效内容。旧版内容以原文或已有摘要整理展示，未区分的证据与推断不冒充已经核实；确实缺失的分区才使用完整视频补齐。已有完整口播直接复用。视频模型通过独立云端转写获得口播文字；口播稿不能当作逐字对齐数据，音效、配乐和精确对齐仍须在制作时核对。模型采样画面中的估计参数不能当成逐帧测量或原作者真实制作过程。

制作规范参考 Remotion 官方文档：[工程基础](https://www.remotion.dev/docs/the-fundamentals)、[Sequence 时间线](https://www.remotion.dev/docs/sequence)、[帧驱动动画](https://www.remotion.dev/docs/animating-properties)、[渲染](https://www.remotion.dev/docs/render)。

### 三个阅读分区

“口播稿”保留完整转写；“视频内容分析”先充分讲清作者的主要内容，包括重要观点、必要解释、关键例子、条件和结论，再在下方补充具体信息、操作测试与画面结果。篇幅随实际信息量变化，不限制为固定句数、段数或字数；信息少则简短，信息多则充分展开。“Remotion 制作规范”单独回答视频如何呈现及制作时如何参考。普通详情默认进入内容分析，三个分区都能在页面内完整阅读、复制和下载，切换分区与字号不会发起分析。尚未分析时明确显示缺失，不根据标题编造摘要。

内容分析继续兼容现有五字段结构：主要内容必填，四个补充字段仍须是字符串，但没有相应信息时允许为空，页面不显示空栏目，也不将其判为待付费补全。来源和重要限制用自然语言说明，避免反复堆叠证据标签。旧版保存文字原样保留，新规则不会自动改写历史结果或触发模型重跑。

提示气泡支持点击关闭，也保留自动消失。日常检查最新 5 条非置顶作品，按视频 ID 去重；已有视频更新互动快照，不重复新增视频。

## 完整抓取与自动恢复

视频分析任务由主机统一管理完整视频获取的三次总尝试（首次加两次重试）。每次重新获取同一目标的媒体地址、下载并校验，逐步增加等待间隔，并设置单次时限。前两次失败仍保持处理中并显示“正在重新获取视频，尝试 2/3”或“尝试 3/3”；确认删除、无权限或必须重新登录时提前停止。任务可以取消，取消后不会继续安排尝试。

取得有效视频后，后续步骤在任务内复用临时媒体。云端口播使用异步任务查询的有限恢复，不因查询失败重复提交；视频模型超时且无法确认执行状态时保留诊断与用量，交由用户核对。结果保存使用独立有限重试，不重新生成。若 SQLite 暂时无法保存，已返回的文字和用量在本机 `pending-analysis-results/` 保留以便恢复写入，不保留媒体或凭据。任务最终成功、失败或取消后仍按原规则清理临时媒体。

最终错误显示失败阶段、实际尝试次数、最后错误、已保留分区和必要操作。“复制诊断信息”提供任务/视频标识、各次实际错误和版本，排除 Cookie、密钥、令牌和签名地址。历史已保存内容不会因为新的获取任务失败而被清空。

一次检查中，详情页文字先加载而媒体未就绪时，程序会激活已校验的视频并等待实际字段齐全；仍有异常时最多重新尝试 3 次。只有账号本轮全部视频的必要字段通过校验，才写入并显示“已完成抓取”。不完整结果不会作为成功提交，也不会把未知互动数记为零。旧版本留下的待处理视频会在当前检查中一并恢复，按视频 ID 去重。不可恢复的阻断仍如实记录失败原因。
