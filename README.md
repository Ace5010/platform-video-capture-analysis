# 内容情报台

本机作为数据主机运行的多设备内容监控工作台。当前只启用抖音，并为小红书、哔哩哔哩和 YouTube 保留入口。账号、视频元数据、互动快照、口播稿和 AI 分析永久保存在主机 SQLite；不保存完整视频，也不采集评论正文或播放量。

## 当前功能

- 监控账号数量不设产品上限，保存主页链接、名称和真实头像。
- 首次建档抓取近 30 条非置顶视频；日常仅在用户主动发起时检查最新 3 条非置顶视频。
- 所有账号逐个执行、按账号切换分析，并按账号 ID 与视频 ID 去重。
- 最新视频自动并入该账号的总数据分析。
- 保存标题、正文文案、封面、原视频链接、发布时间、时长，以及点赞、评论、收藏、分享四项快照。
- 四项互动分别汇总，并以每条视频为节点绘制走势；不显示没有业务含义的进度百分比或公开互动合计。
- 每条视频提供一个“AI 分析”按钮。只有点击后才临时获取该条完整原视频，同时生成并永久保存“原视频口播稿”和“AI 视频分析”；首次 30 条和日常采集不会自动消耗 AI。
- 口播稿由本机 faster-whisper 识别，再由本机 CT-Transformer 标点模型补齐中文标点；旧稿在主机启动时也会从原始识别稿重新补齐，过程中不上传云端且不改动识别文字内容。
- 每次 AI 分析（包括失败和重试）都会单独保存接口返回的 Token、请求 ID、官方原价估算和计价快照；未收到完整用量时只展示已知 Token 并标记“待账单核对”，不会误报为 0 元。免费额度、资源包和优惠后的实际扣款仍以百炼账单为准。
- 手机或其他电脑可登录同一网页，发起抓取与 AI 分析。实际采集仍由主机上已登录抖音的 Chrome 扩展执行。

## 完整视频分析链路

1. Chrome 扩展打开被选视频的标准详情页，前后校验视频 ID，只接受已绑定到目标作品的抖音 HTTPS CDN 媒体源，并优先选择分辨率、码率和文件大小更高的完整源。
2. 主机默认把媒体临时下载到项目目录下的 `data\host-service\tmp`，用 ffprobe 校验它确实包含视频流，并核对下载时长与目标页面时长。若视频与音频是分离流，只使用 FFmpeg `-c copy` 做无损封装。
3. 同一个完整媒体文件并行进入本地 `faster-whisper large-v3` 口播识别与 Qwen 输入准备。没有关键帧替代、OCR 代理、降分辨率、转码压缩或“失败后只交文本”的隐藏降级。
4. 不超过 7 MiB 的完整文件直接以 Data URI 发送（为 Base64 编码后的 10 MB 限制预留空间）；更大的文件会使用百炼官方临时上传凭证原样上传，再把临时 `oss://` 引用交给 `qwen3.8-flash`。如果超过单文件或模型视觉预算，只做按时间连续的无损分段，所有分段仍会完整分析。
   - 工作台不会自行抽关键帧。Qwen 服务端仍会按视觉模型机制抽帧；请求将单帧与总像素预算设为 Qwen3.8 允许的最高值，并在 10 fps 上限内按视频时长动态取样，避免默认参数悄悄降低画面细节。
5. Qwen 返回摘要、视频主题、核心观点、画面内容、人物行为、字幕与画面文字、结构与叙事。不会分析环境音、语气、音乐、开头钩子、高潮或结尾引导。
6. 成功或失败后立即删除本机临时媒体；SQLite 只保留口播稿、结构化分析、来源哈希与状态。

重要：工作台和数据库都在本机，但点击“AI 分析”后，完整视频、标题、正文和本地口播稿会发送给阿里云百炼。这是使用云端视觉模型所必需的联网动作，采集本身不会触发它。

## 首次安装

需要 Node.js、Python 3 和 FFmpeg/ffprobe。然后在项目目录运行：

```powershell
npm install
npm run setup:asr
npm run dev
```

`setup:asr` 安装本地识别依赖；`large-v3` 模型文件会在第一次执行 AI 分析时下载一次并缓存，之后口播识别在本机运行。可在正式使用前先完成这次下载，避免首条视频等待时间较长。

`npm run dev` 固定启动两个进程：

- 工作台：`http://localhost:3000`，监听局域网地址。
- 主机 API、SQLite、任务队列与本地 ASR：`http://127.0.0.1:43129/health`，同时监听局域网地址。

端口固定是为了让浏览器安全来源、Cookie 和 API 白名单保持一致；若端口被占用，脚本会明确失败，不会静默跳到另一个端口。

第一次打开 `http://localhost:3000` 时，先设置至少 10 位的局域网访问密码。首次设置和 Qwen API Key 录入只能在主机的 localhost 页面操作。API Key 使用 Windows 当前用户 DPAPI 加密，文件位于：

```text
项目目录\data\host-service\qwen-secret.dpapi
```

它不会写进浏览器 localStorage、SQLite、Git 或请求日志。之后在页面的“配置 Qwen”中粘贴 Key 即可；没有 Key 时，采集和数据分析照常工作，只有视频 AI 分析按钮会被阻止。

## Chrome 采集组件

在 `chrome://extensions` 开启开发者模式，选择“加载已解压的扩展程序”，加载本项目的 `chrome-extension` 文件夹。代码更新时需要在扩展卡片点击一次“刷新”载入新脚本；运行过程中如果 Chrome 扩展上下文被重启，工作台会自动重载桥接并重新配对，不需要每次分析前手动刷新。当前扩展版本为 `0.8.0`；完整视频分析要求已连接的组件版本不低于 `0.8.0`，且组件必须报告 `analyze_video` 能力。

采集要求主机 Chrome 保持运行并维持抖音登录状态。系统不会定时自动检查；本机、手机或其他已授权设备可主动提交采集任务，任务结果经本机鉴权队列写入 SQLite。任务提交后工作台网页可以关闭，但 Chrome 完全退出或电脑休眠时无法继续采集。

## 其他设备访问

1. 在主机执行 `npm run dev`，记下终端输出的 `http://主机局域网IP:3000`。
2. 确认当前网络是可信家庭/办公网络，并在 Windows 设置中把它设为“专用网络”。
3. 用管理员 PowerShell 在项目目录执行：

```powershell
.\scripts\allow-private-network.ps1
```

脚本只对“专用网络”的本地子网放行 TCP 3000 与 43129；若当前只有“公用网络”，它会拒绝修改。不要做路由器端口映射，也不要把这两个端口暴露到互联网。

4. 手机或另一台电脑在同一局域网打开终端给出的地址，用主机设置的访问密码登录。它们可以发起首次建档、最新检查和 AI 分析，但主机、网站进程及主机 Chrome 必须保持运行。

## 数据与隐私

- 主数据默认保存在项目目录下的 `data\host-service\monitor.sqlite3`（WAL 模式）。可通过 `DOUYIN_HOST_DATA_DIR` 或 `DOUYIN_DATA_DIR` 环境变量覆盖整个运行数据目录。
- 旧版 localStorage 首次迁移前会创建本地 JSON 备份，迁移校验成功后才标记完成。
- 浏览器与扩展之间使用带 CSRF 的密码会话和仅回环可用的 connector token；签名 CDN URL 不写入扩展持久存储或日志。
- 采集任务离线等待 30 分钟后过期；AI 视频分析任务会保留 7 天，避免因 Chrome 临时断开而丢失已提交的分析请求。领取中的任务采用短租约并持续续期，断线或扩展重启后会自动回到队列；采集结果事件具有幂等 ID，重复提交不会生成重复视频或快照。
- 采集器只处理公开页面数据。页面返回空列表、跳转到其他账号/视频或字段不完整时会失败，不会写入半成品或伪造数据。

## 验证命令

```powershell
npm run test:bridge
npm run test:scheduler
npm run test:connector
npm run test:host
npm run lint
npm run build
```

`test:host` 使用临时数据库、假 API Key 与模拟完整视频，不会访问抖音或调用真实 Qwen，也不会产生费用。真实 Qwen 调用需等你在网页中录入自己的 Key 后再验证。
