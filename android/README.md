# 内容工作台 Android

当前版本 `0.1.3`（versionCode 4），应用 ID `com.personal.contentworkbench`，最低 Android 8.0。应用图标与本地、在线工作台统一使用红橙渐变无圆环版，资源由 `node scripts/generate-brand-icons.mjs` 从同一张原图导出。Android 自适应图标跟随桌面圆形或圆角裁切，兼容位图四角透明。覆盖安装须使用相同发布签名。

## 安装和使用

将 `outputs/android/content-workbench-release.apk` 传到手机安装，打开“内容情报台”，输入现有工作台密码。电脑须开机、联网，主机服务和现有远程通道须保持运行；休眠后手机无法访问后台。

手机与电脑使用同一个 SQLite 后台及任务队列，账号、视频、口播稿、分析结果无需复制。前台约每 4 秒刷新，恢复前台或联网时重新读取。退出手机 App 后，已提交的后台任务仍由电脑执行。断线不会自动重发识别或分析请求。

手机直接加载 `cloudflare-pages.json` 中的正式网站 `https://content-workbench-swq3506.pages.dev/`，支持内容浏览、账号切换、视频播放与分析、链接分析、互动图表及现有远程账号管理操作。API Key 设置、后台登录窗口等仅限电脑本机的功能仍保留原有限制。

## 实现

APK 只包含原生 WebView 外壳，不内置 HTML、CSS 或网页脚本。首页与资源均从正式 HTTPS 网站加载，启动和重试时重新验证首页缓存。Pages 入口仅向 `cloudflare-host.json` 中的固定原站转接页面、资源和 `/host/*`，复用原有 Worker、私有通道和受限后台；不复制网页、数据库或任务。入口验证正式来源，保留密码 Cookie 和 CSRF，不接受任意上游地址，不自动重试写请求。外部 HTTPS 链接交给浏览器打开，视频全屏由原生容器承接，返回键先退出全屏。

数据库、API Key、登录密码、测试数据和签名私钥均不打包。App 禁止明文 HTTP、文件 URL、第三方 Cookie 和系统备份；Release 不开放 WebView 调试。签名配置及构建产物已加入 Git 忽略规则。

从 `0.1.0` 升级时，用同一签名直接覆盖安装一次，无需卸载或清除数据。之后发布网页界面更新，重新打开 App 即可加载新版；原生能力变更仍需更新 APK。打开网站失败时提供“重新连接”，不会重发采集或分析任务。网站发布与 APK 构建是两个独立步骤，不能把本机开发页面更新当作网站已经发布。

从旧 `workers.dev` 地址切换到新网址时，使用原访问密码重新登录一次；账号和结果继续保存在原后台。

## 网站入口维护

正式 Pages 项目为 `content-workbench-swq3506`，入口使用平台提供的免费网址，无需购买自有域名。原网站继续按已有 Git 发布流程更新，Pages 实时转接最新内容。只有入口代码或来源配置变化时，才需要重新部署入口包。

```powershell
node scripts/build-pages-entry.mjs
node --experimental-strip-types scripts/test-pages-entry.mjs
```

将 `outputs/cloudflare-pages/` 的完整内容上传到该 Pages 项目，包含入口文件、图标、手机桌面清单与品牌样式。入口继续转接原网站，只在首页添加图标引用并独立提供公开图标资源；应用脚本与后台接口继续使用原有上游。预览网址被入口代码拒绝，验收应使用 `cloudflare-pages.json` 中的正式网址。原 `cloudflare-host.json` 及受限后台的来源配置保持对应原 Worker，不需要重配隧道凭据。

## 构建

使用 JDK 17+、Gradle 8.11.1、Android SDK 35。脚本优先复用同级 Pocket 的 Android 工具，并兼容旧日程系统路径，也可显式传入 `-ToolsPath` 或 `-JavaPath`、`-SdkPath`、`-GradlePath`。

首次仅在没有签名配置时执行：

```powershell
./scripts/setup-android-signing.ps1 -JavaPath <JDK目录>
```

独立签名文件保存在当前用户的 `%LOCALAPPDATA%/ContentWorkbench/signing/`，配置为 `android/keystore.properties`。应私下备份，后续版本使用同一签名；不要提交或公开这些文件。

2026-10-25 经用户授权，原签名丢失后重新签名并重装。自 `0.1.3` 起必须保留本机新签名继续覆盖升级。密钥及配置已有两份 Windows 当前用户 DPAPI 加密备份，位于 `%USERPROFILE%/.local/share/observe/signing-backups/` 和项目忽略目录 `.runtime/signing-backups/`；两份均已解密比对验证。不得重新生成其他密钥代替。

```powershell
./scripts/build-android.ps1 -Validate
```

脚本构建 APK，运行单元测试与 Lint，并确认正式包没有内置网页及测试数据。正式包输出到 `outputs/android/content-workbench-release.apk`，构建时复用本机原签名。

需要隔离安卓运行验收时，先执行 `npm run build`，再运行 `./scripts/build-android.ps1 -Validate -BuildInstrumentation`。只有独立的测试 APK 包含构建网页与模拟数据；正式包始终从网站加载。测试模式隔离业务 API，`mode=live` 仅访问正式网站登录页，不输入密码或发起付费分析。
